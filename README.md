# Brand Router 实验面板下载

当前版本：**v0.3.4，2026-10-09 保持登录与一键更新测试版（实验应用）**。旧版目录保留用于核对。

这是安装在已有 iStoreOS 上的实验应用包，不是完整固件。**固定 MAC → VLESS 转发及专属 DNS 已接入；租约轮询、动态会话尚未接入运行。** 固定模式须安装兼容的 Xray/sing-box 核心、通过授权及环境校验，再明确应用配置。其他协议目前可保存不等于已接入真实转发。不会自动检查或安装新版本。

本仓库公开可读。它仅包含版本化安装器、设备端应用包、初始化脚本、激活签发方公钥、版本信息、校验表、根目录发布索引及说明。应用包中的设备端 Lua/JavaScript 等代码同样公开可读；管理员程序、签发私钥、设备私钥、客户配置、真实节点、账号密码、恢复码和数据库不在这里。

## 安装条件

- 已有 **iStoreOS 24.10 x86_64**，通过设备的 SSH 终端以 root 操作；不适用于 Mac、Windows 或其他路由系统。
- 建议仅在已备份的实验设备上使用。标称最低 4GB RAM / 16GB SSD；实际检查至少 3328MiB 系统可见内存、13500MiB 可写分区、512MiB 可用内存，安装及备份后仍须保留 2GiB 磁盘余量。
- 设备必须能通过有效 HTTPS 证书访问 GitHub；下载前已有 `curl`、`sha256sum`、`tar` 等基础工具。
- iStoreOS 软件源必须保留签名检查。缺少的应用依赖通过系统软件源安装，不强制依赖、不升级整个系统。
- 首次初始化要求唯一的 LAN IPv4，端口 28283 未被占用，且不存在旧的品牌状态或冲突的专用客户账号。

安装不会自动扩盘、刷写固件或修改 network/dhcp/firewall。系统依赖的安装可能运行依赖包自带的重载脚本。应用备份不能代替完整系统备份。

## 先检查，再安装

下面这段默认只预检，不安装。确认检查通过且已备份后，将第一行的 `plan` 改成 `apply`，重新运行整段。

```sh
MODE=plan
(
    set -eu
    umask 077
    [ "$(id -u)" = 0 ] || { echo 'root_required' >&2; exit 1; }
    WORK=$(mktemp -d /tmp/brand-bootstrap.XXXXXX)
    trap 'rm -rf "$WORK"' EXIT
    curl --fail --location --proto '=https' --proto-redir '=https' \
        --connect-timeout 15 --max-time 180 --max-filesize 1048576 \
        --silent --show-error \
        https://raw.githubusercontent.com/mabiao210121/brand-router-downloads/main/v0.3.4/install.sh \
        -o "$WORK/install.sh"
    printf '%s  %s\n' \
        'feae5e8a92f2f4c43397274b500d15adf55018efcedb727ce09bdc63b29cbd29' \
        "$WORK/install.sh" | sha256sum -c -
    sh "$WORK/install.sh" "$MODE"
)
```

安装器固定下载 v0.3.4 的应用包、初始化脚本和公钥，分别核对 SHA256 后再执行，不会自动跟随其他版本。

第一次成功安装后，终端会显示局域网 HTTPS 地址、面板账号 `root`、空初始密码和本机恢复码。请把恢复码保存在设备以外的安全位置，不要上传终端输出。这里的 `root` 仅为面板账号名，不会清空或修改 Unix/SSH root 的密码。

局域网 HTTPS 使用设备生成的自签名证书，浏览器会提示证书不受公共机构信任；请先核对设备和地址。

安装后仍为待激活状态。管理员另外为设备机器码签发激活码，并在签发时自行设置到期时间；本下载包不包含激活码或默认有效期，也不会自动签发授权。激活并不代表尚未接入的代理业务已经可用。

## 面板账号与密码恢复

- 激活后，新装设备使用 `root` 和空密码首次登录，只能先进行账号设置。设置 8–128 字节密码，或明确勾选免密确认后，才能访问业务配置。免密意味着能访问该面板的其他人也可能管理它，勿将面板暴露到不可信网络。
- 已有设备升级不会清空原来的面板密码，也不会自动把旧账号迁移成 `root`。登录后在系统设置提交当前密码，才切换到新的面板账号模式；原 Unix/SSH/rpcd 凭据不由此修改。
- 修改密码、切换登录模式或使用恢复码后，旧登录会话和旧恢复码失效。新恢复码只展示一次，保存后再确认关闭；常规状态刷新不会提前关闭恢复表单或新码窗口。
- 忘记密码时，在登录或激活/过期页面选择“忘记密码 / 恢复面板密码”，用本机恢复码重设密码，无需刷机。恢复码为一次性使用，成功后须保存换发的新码。
- 恢复码也丢失，或旧版尚未生成恢复码时，联系维护管理员通过已授权的 SSH/root 维护入口重置面板账号。不要删除账号、授权或业务文件。密码恢复不会延长授权，过期后业务仍不可用。

## 应用更新与恢复

“系统更新”页按“检查新版本 → 下载并检查 → 确认安装”操作。更新源固定为本仓库根目录 [stable.json](stable.json)，执行需要有效授权、管理权限、登录会话及请求校验。离线导入也须先联网取得该版本的官方元数据，再导入大小和 SHA256 完全匹配的文件，上限 2 MiB；不能完全脱离可信元数据安装任意压缩包。

安装保留账号、设备身份、授权、节点和基础网络配置。已有固定转发会从已应用快照重编规则，不会把尚未应用的草稿投入运行；旧版没有快照且存在待应用修改时拒绝更新并回退，须先处理这些修改。应用备份和新恢复包在受控流程中保留，安装后的可捕获记录/状态/服务验证故障会尝试回退；成功后可选择恢复更新前的应用。它不是整机快照或业务数据回退，也不会卸载已安装的共享依赖。

开始更新前先保存或放弃页面草稿。面板服务重启会使当前会话失效，需要重新登录。出现中断或恢复失败时停止重复尝试，由维护管理员检查本机备份和任务状态；物理断电、强制终止及自动崩溃恢复未完成独立验收。

新面板账号文件建立后，面板会拒绝回退到不支持该账号格式的旧应用。不要通过手动覆盖安装 `v0.1.0` 绕过兼容性限制。旧版文件保留用于历史核对，不是通用降级入口。

## 重复安装与异常状态

健康的已有安装会验证完成标记、配置、专用客户账号、证书与私钥匹配、证书有效期和激活公钥，再重启面板加载已安装的代码。账号、设备身份、授权和已保存配置不会重新初始化。

若提示 `existing_brand_setup_incomplete`，表示状态缺失、损坏或没有有效完成标记。**不要删除原状态、伪造完成标记或反复重装来绕过检查。** 保留设备数据，由管理员核实并修复后重试。旧版即使曾正常安装，也可能因为没有完成标记而被拒绝；不会自动把它认定为完整安装。

首次初始化遇到可捕获错误时，会尝试恢复原客户账号配置并清理本次创建的入口文件。断电或强制终止后的残留状态需要人工检查；不承诺断电后自动修复。成功更新会重启面板，当前登录会话可能中断。

应用文件安装器会输出本机备份编号。回退由应用包内层 `install.sh rollback 备份编号` 处理，仅恢复该安装器管理的应用文件，不自动卸载共享依赖，也不是整机、账号或授权状态恢复。外层下载入口只接受 `plan` / `apply`。

## 可选 Tailscale 远程协助

更新后进入“系统设置 → Tailscale 远程协助”。点击“下载并安装 Tailscale”时才从官方稳定源获取最新 amd64 程序；本轮官方 1.104.1 下载约 39.2 MiB、两个程序占约 74.2 MiB，具体以后续版本为准。它不打进每次品牌应用更新包。

安装完成后点击“开启协助 · 30 分钟”。首次需要把显示的授权链接交给管理员，由管理员登录 Tailscale 接纳设备；管理员的 Mac 也必须有该网络的访问权限。获得组网地址后可复制 SSH 连接指令，仍需原系统 SSH 凭据。没有账号授权、没有实际连接验证时，不代表已能远程排查。

工具使用 userspace networking，不接收 DNS/路由、不接管上网、不通告客户内网或出口、不开放公网 SSH/Funnel。有权限的 Tailscale 设备可访问本机服务，应通过 Tailscale 管理端限制访问权限。点击“关闭协助”或到期后停止进程，重启后保持关闭；设备身份和已安装程序保留。品牌应用升级或回滚也会核实关闭。未确认进程退出时保留告警并阻止继续升级，不能把清除会话等同于关闭。

原生隔离 x86 iStoreOS 已验证官方安装、授权链接、两项受监督进程、到期与主动停止、无开机链接及网络/DNS/防火墙配置和路由前后一致。真实客户设备和跨网络 SSH 尚待用户安装、授权后验收。用户通过面板亲自更新，本次发布不代为安装。

## 本次修复与验证范围

- 检查版本只查询信息，不自动下载或安装；必须主动下载并确认安装。

## 0.3.4 登录和更新体验

设备面板取消一小时自动退出，新登录保持到主动退出、改密/恢复、授权失效、设备重启或浏览器清理登录数据。浏览器 Cookie 采用 400 天滚动保留，成功访问时续写；不承诺浏览器无限期保存。短暂断网或系统验证服务暂时不可用不会清除登录。旧版本登录需要更新后重新登录一次，签发后台登录策略不变。

正常更新只需“检查新版本 → 立即更新”，确认后后台自动完成下载、校验、空间检查、备份和安装；失败停止或沿原流程回退。离线导入收在“其他更新方式”。从 0.3.3 及更早版本升级这一次，仍使用旧页面的“下载并检查 → 安装已检查版本”。
